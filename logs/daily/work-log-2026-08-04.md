## Mentor / 決策

- PoC 的存在理由必須是補足 Skill 3 無法回答的決策證據；不是因為技術分數高或成本低就自動部署。
- WorkSpaces AI Agents 雖獲 4.6 / 5，仍須先登錄專用 Skill 4 recipe 並確認目標區域支援，才可提交具名 PoC 核准。
- 跨電腦延續以 GitHub 為 source of truth；原始 runtime artifact、Console 登入狀態與本機憑證不應依賴 GitHub 傳遞。

## 問題與下一步

## 17:12 補強 Skill 4 的部署前檢查

今天下午檢查並套用了新的 Skill 4 設計：以「可部署 recipe」作為真正進入 PoC 的門檻。這代表一篇文章即使在 Skill 3 分數很高、也能產生估價，只要還沒有明確寫出要建立哪些資源、怎麼驗證成功、怎麼清理、怎麼蒐證，就不能直接進入 Skill 4 建立 AWS 資源。

這次也補上整條流程的分段計時，讓 Skill 5 可以區分程式執行時間與人工等待時間，之後比較容易說明 AI PM 到底節省了哪一段時間、哪一段仍需要人類決策。

針對 WorkSpaces AI Agents 這篇文章，系統現在會正確擋在 Skill 4 前：它目前只有草稿型驗證設計，還不是可部署 recipe。即使手動把授權打開，部署前檢查也會因缺少可部署 recipe、成本上限、清理策略、成功條件與證據計畫而拒絕繼續。這是預期行為，避免 AI 在沒有明確驗證設計時自行建立雲端資源。

驗證結果：相關 Skill 4、S3-S4、S5、成本估算與分段計時測試共 91 項通過，並完成 Python 語法檢查。
