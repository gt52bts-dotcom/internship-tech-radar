## Mentor / 決策

- 後續 Skill 3 起維持單項評估，不再做 top 3 全流程比較；人類選定一項後才進入 Skill 3、Skill 4、Skill 5。
- Skill 4 就是會建立 AWS 資源、可能產生費用的受控 PoC，不再拆出另一套「低風險 Skill 4」標準。
- Skill 3 必須先產出完整 PoC 報價單，人工同意後才能進入 Skill 4。
- cleanup 前先記錄即時用量快照；實際帳務成本仍等 Billing / Cost Explorer / CUR 證據，不在 cleanup 前等待帳單入帳。
- Console 截圖內容目前仍靠人類目視確認；系統只驗 metadata、run ID、stack、region、分享管道與 SHA-256，不能宣稱已自動理解圖片內容。

## 問題與下一步

- 實際 AWS 帳務成本尚未能歸因到單一 run；下一步要設計 Cost Explorer / Billing / CUR 的對帳方式，讓 Skill 5 能補上預估成本與實際帳務成本比較表。
- Infrastructure Composer 截圖流程目前仍偏人工；下一步可把 Playwright 開 Console、截中間 canvas、上傳 GUI 或對話框、等待人類確認這段流程做成固定 template。
- Amazon Connect Customer Data Lake 目前只有 Skill 3 一般估價與 interim 報告，尚未有可部署 recipe、可用 Connect instance 與完整部署條件，因此不應寫成已完成真實 PoC。
- 五個 Skill 已能支援小型可控試驗，但還不是完整 production AWS 系統；Cognito、API Gateway、EventBridge、Step Functions、CloudWatch alarms、正式 CI/CD 等仍屬下一階段。
