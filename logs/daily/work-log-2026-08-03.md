# 每日實習日誌 - 2026-08-03

## 今天在做什麼

今天主要把雲端技術雷達的五階段流程整理得更像主管能審查的決策流程。重點是先讓人看懂新聞、看見價值與預估成本，再決定要不要花錢做 PoC；實際做完 PoC 後，也要留下資源、權限、耗時與清除結果，不能只靠截圖或口頭說明。

## 今天做了什麼

- 調整 Skill 3 的決策流程。原本是在還沒看到報價時就先請人選候選，容易造成資訊不足；今天改成先由系統產生分數、成本估算與架構圖，再讓人類決定是否進入 Skill 4。
- 移除舊的「信心指標」與必要的人工預選步驟。之後是否進入 PoC，改看分數、已知阻礙、預估成本、是否有可部署方案，以及具名核准。
- 在 Skill 1 加入新聞解釋能力。系統不只抓到文章，還會整理原文重點、以前與現在的差異、最小可驗證架構，以及可能的應用情境。
- 調整 Skill 3 的人類閱讀報告。報告會先用中文說明新聞在做什麼，再放架構圖、分數、成本假設與是否值得進入 PoC；圖片會直接顯示在報告裡，不再只放連結。
- 把 Skill 4 的確認方式從「截圖存在」改成「資源盤點」。因為程式不能真的看懂截圖內容，所以改由 AWS 回傳的資源清單來確認實際建立了什麼、和報價是否對得上、用了哪些權限，以及清除前有哪些用量紀錄。
- 新增分段耗時紀錄。流程會分開記錄程式執行時間與人工等待時間，讓後續報告能說明整個 PoC 最耗時的是自動化步驟，還是等待人工確認。
- 修正成本估算邏輯。Lambda 測試情境補上日誌服務費用；金額加總改成用未四捨五入的數字計算，避免明細與總額對不起來；S3 Files 的磁碟容量也改由情境假設決定。
- 移除 Skill 5 的實際帳務比對。短時間 PoC 無法立刻得到可歸因的 AWS 帳務資料，所以報告改為清楚說明：這是部署前公開牌價估算，不是 AWS 帳單。
- 擴充 Skill 5 報告內容。報告新增技術意義、報價與實際資源對照、資源盤點、權限面、耗時與成本限制，讓結論更像可審查的證據包。
- 用 Lambda 自主管理程式碼儲存與 S3 Files 兩篇 AWS 官方文章驗證新版流程。兩個案例都已完成資源清除與結案報告；S3 Files 也完成實際部署、雙向資料驗證、資源盤點、清除前快照與清除後回查。

## Mentor / 決策

- Skill 3 是部署前的正式決策點。同一份報告要讓人同時看懂新聞價值、最小架構、分數、報價與是否有可部署方案。
- 不再使用信心指標。是否進入 Skill 4，由分數門檻、已知阻礙、報價、可部署方案與具名核准共同決定。
- Console 截圖只能作為輔助人工證據，不能宣稱程式已經看懂圖片內容；主要確認依據改為資源盤點。
- Skill 5 不做預估成本與實際帳務成本比較。短時間 PoC 的價值是驗證部署可行性、服務整合、權限邊界、執行結果、清除可重現性與報告證據鏈。
- S1-S5 的人類可讀報告都要用中文呈現狀態與結論。
