# 每日實習日誌 - 2026-08-03

## 今天在做什麼

今天主要不是新增一個單點功能，而是把雲端技術雷達的 S1-S5 流程重新整理成更合理的決策鏈：先讓人看懂新聞、看見技術價值與預估成本，再決定要不要進入 PoC。下午也把 Skill 4 的人工截圖確認改成可機器比對的資源盤點，讓 PoC 結論更容易被主管或 Mentor 回查。

## 今天做了什麼

- 合併 Skill 3 的 PoC 決策關卡。原本 S2 後先人工選候選，決策者還沒看到報價就要決定要不要往下做，資訊順序不合理；今天改成 Skill 3 對候選產生分數、報價與單一 `poc_decision_gate`，讓人類在同一份報告裡決定是否同意進入 Skill 4。
- 移除舊的信心門檻與人工 shortlist 主流程。`human_shortlist_gate`、`needs_human_shortlist` 不再是必要流程，`--shortlist` 只保留為選用過濾器；報告改用滿分制加權分數、blocker、報價 readiness、recipe readiness 與具名 approval 來判斷。
- 在 Skill 1 新增可重現的解釋層。`s1_explanation.py` 用規則式方法產生原文重點、前後差異、最小實作架構與可能應用情境；原文重點帶字元區間，測試會檢查切片內容是否真的對應原文。
- 調整 Skill 3 人類閱讀報告。報告現在先用中文說明新聞在做什麼，再呈現 PoC 架構圖、分數、成本假設與是否值得進入 Skill 4；HTML 是主要產物，架構圖直接嵌入報告，不再只放 Markdown 圖片連結。
- 把 Skill 4 close gate 從 Console 截圖 metadata 改成 structured resource inventory。因為程式只能驗證 PNG 存在、hash 與分享欄位，不能真的判讀圖片內容；改用 CloudFormation `describe-stack-resources` 的結構化結果後，資源清單、報價是否漏列、權限面與 cleanup 前狀態都可以自動比對。
- 新增 `s4_inventory.py` 與分段計時 `pipeline_timing.py`。Skill 4 現在可以記錄實際部署資源、報價資源對照、IAM action surface，以及各階段程式耗時與人工等待時間，讓後續 S5 報告能說清楚 PoC 時間花在哪裡。
- 修正成本估算公式。Lambda recipe 補上 CloudWatch Logs 擷取費用；金額加總改用原始 Decimal，避免明細與總額四捨五入後不一致；S3 Files 的 EBS 容量改由情境假設決定，而不是寫死在公式裡。
- 移除 Skill 5 的實際帳務成本比對。`--billing` 參數與帳務 reconciliation 已移除，報告明確標示本流程不做 AWS Billing / Cost Explorer / CUR 的實際成本比對，只呈現部署前公開牌價估算、runtime facts 與限制。
- 擴充 Skill 5 報告章節。新增架構與意義、報價與實際部署資源對照、Skill 4 資源盤點、實際權限面與各階段耗時，讓 final report 不只是結論，而是可以被審查的證據包。
- 同步兩份 Skill 目錄與交接文件。`radar-redesign/skills/` 和 `radar-redesign/claude-gui-handoff/` 的 SKILL.md 有同步更新；也清理舊版工作週誌與簡報檔，避免交接時混到過期產物。
- 用 Lambda self-managed code storage 與 S3 Files 兩篇 AWS 官方文章驗證流程。Lambda 完成 cleanup 與 Skill 5 final；S3 Files 完成 Skill 3 決策報告、人工同意後的 Skill 4 PoC、resource inventory、cleanup 前快照、run-scoped cleanup 與 Skill 5 final。

## Mentor / 決策

- Skill 3 應是部署前的正式決策點：同一份 HTML 報告要讓人同時看懂新聞價值、最小架構、分數、報價與是否有 recipe。
- 不再使用 confidence 作為決策指標。PoC 是否進入 Skill 4 由分數門檻、blocker、報價、recipe readiness 與具名 approval 決定。
- Console 截圖可以作為輔助人工證據，但不能當作程式已判讀圖片內容；Skill 4 close gate 應優先使用 structured resource inventory。
- Skill 5 不做預估成本與實際帳務成本比較。短時間 PoC 的價值是驗證部署可行性、服務整合、權限邊界、runtime 行為、cleanup 可重現性與報告證據鏈。
- S1-S5 的人類可讀報告都要以中文呈現狀態與結論，machine-readable JSON 可以保留穩定英文狀態碼。
