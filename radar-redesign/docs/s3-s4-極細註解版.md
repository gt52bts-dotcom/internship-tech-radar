# S3/S4 極細註解版：先評估，再做低風險驗證

## 1. S3 現在做什麼

S3 只吃 S2 artifact 和 human shortlist request。它不重新搜尋、不改 S2 證據、不自動排名全部候選，也不啟動 PoC。

S3 的輸入契約：

- `input`：S2 comparison artifact，狀態必須是 `ready_for_human_shortlist`。
- `shortlist`：真人最多選 3 個 candidate。

如果沒有 shortlist，S3 會輸出 `needs_human_shortlist`，不會假裝已經進入評估。
不需要另外填公司問題、使用環境或資料限制；S3 直接使用公開證據模式。

## 2. S3 固定 rubric

S3 使用固定權重，不因候選調整：

| 維度 | 權重 | 判斷重點 |
| --- | ---: | --- |
| technical_value | 0.35 | 來源是否證明技術能力、GA、服務範圍與改善向量 |
| adoption_prerequisites | 0.25 | 文件、定價、Region 與導入前提是否清楚 |
| verifiability | 0.25 | 是否能設計 before/after、成功證據與低風險驗證 |
| risk_and_stop_conditions | 0.15 | 是否有停損條件、未知數是否過多 |

成本不列入技術分數。S3 只把成本標成 `unknown` 或留給 S4 的 budget gate。

## 3. Region 在 S3 的位置

`region_unknown` 不阻擋 S3 或 PoC 審查，只會讓 `adoption_prerequisites` 扣分，並在候選中留下 review note。

S3 v3 會分開記錄：

- `recommend_low_risk_validation`：分數至少 3.25、信心至少 medium，且沒有 Bedrock／S3 hard blocker。
- `eligible_for_poc_review`：分數至少 3.75、信心至少 medium，且沒有 hard blocker。
- `poc_review_notes`：Region 或 pricing 尚未證實時留下提醒。
- `recommend_s4` 與 `eligible_for_paid_poc_review`：只為舊版 consumer 相容保留。

## 4. S4 現在做什麼

S4 讀 S3 artifact，建立 validation artifact。預設不需要 approval，因為預設只做低風險驗證。

S4 會檢查：

- S3 是否為 `recommend_low_risk_validation=true`。
- 若要求 PoC，是否另為 `eligible_for_poc_review=true`。
- source URL、score、confidence、stop conditions 是否存在。
- 若要求 PoC，是否有真人 `approved_by`。
- 成本上限預設使用系統的小額 policy；只在需要更嚴格時覆寫。

目前 S4 永遠不會自動建立 AWS resources。即使 PoC gate 通過，也只會標成 `poc_ready_for_manual_start`。

## 5. 這次本機驗證怎麼跑

```powershell
cd "C:\Users\youhs\Documents\實習專案\radar-redesign"

python -m agentic_cloud_radar.cli s1 `
  --input .\samples\landscape-ga-singapore-request.json `
  --output .\out\s1-region-warning-check.json

python -m agentic_cloud_radar.cli s2 `
  --input .\out\s1-region-warning-check.json `
  --output .\out\s2-region-warning-check.json
```

接著準備一份 shortlist request。這份檔案只需要由人類挑最多三個 candidate。

```powershell
python -m agentic_cloud_radar.cli s3 `
  --input .\out\s2-region-warning-check.json `
  --shortlist .\out\s3-local-shortlist-request.json `
  --output .\out\s3-local-evaluate.json

python -m agentic_cloud_radar.cli s4 `
  --input .\out\s3-local-evaluate.json `
  --output .\out\s4-local-validate.json
```

本次驗證結果：

- S3：`evaluated`，評估 3 個，3 個建議進 S4。
- S4：`validated_low_risk`，驗證 3 個，全部是低風險 validation artifact。
- PoC ready：依公開證據門檻決定。
- cloud resources created：false。

## 6. 可以宣稱與不能宣稱

可以宣稱：

- S3/S4 本機 Skill slice 已能讀前一階段 artifact 並輸出下一階段 JSON。
- Region unknown 不再卡住 S3，而是留下部署提醒。
- S4 目前沒有建立 AWS 資源，cleanup 狀態為不適用。

不能宣稱：

- 不能說正式 PoC 已完成。
- 不能把一個 sandbox recipe 的結果外推到所有環境。
- 不能說 candidate 已在新加坡可用。
- 不能說有官方價格估算；S3 仍把 pricing unknown 留給後續查證。
