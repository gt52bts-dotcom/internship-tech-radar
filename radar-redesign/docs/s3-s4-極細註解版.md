# S3/S4 極細註解版：先評估，再做唯一受控 PoC

## 1. S3 現在做什麼

S3 只吃 S2 artifact 和單項 human selection request。它不重新搜尋、不改 S2 證據、不自動排名全部候選，也不啟動 PoC。

S3 的輸入契約：

- `input`：S2 comparison artifact，狀態必須是 `ready_for_human_shortlist`。
- `shortlist`：真人只能選 1 個 candidate。

如果沒有 shortlist，S3 會輸出 `needs_human_shortlist`，不會假裝已經進入評估。
不需要另外填公司問題、使用環境或資料限制；S3 直接使用公開證據模式。

## 2. S3 固定 rubric

S3 使用固定權重，不因候選調整：

| 維度 | 權重 | 判斷重點 |
| --- | ---: | --- |
| technical_value | 0.35 | 來源是否證明技術能力、GA、服務範圍與改善向量 |
| adoption_prerequisites | 0.25 | 文件、定價、Region 與導入前提是否清楚 |
| verifiability | 0.25 | 是否能設計 before/after、成功證據與受控 PoC |
| risk_and_stop_conditions | 0.15 | 是否有停損條件、未知數是否過多 |

成本不列入技術分數，但不能因此消失。S3 對已登錄 recipe 呼叫 `agentic_cloud_radar/costing.py`，建立 `poc.cost-quote.v1`：低／預期／高三種情境、逐項費率、公式、小計、官方來源、有效期限與建議核准上限。沒有費率模型時仍建立 `needs_registered_cost_model` 的待補報價 artifact，不填造數字。

## 3. Region 在 S3 的位置

`region_unknown` 不阻擋 S3 評估，只會讓 `adoption_prerequisites` 扣分，並在候選中留下 review note。真的要進入會建立 AWS 資源的 S4 付費 PoC 時，Region 必須已由官方證據確認，或在 approval 明確寫入 `region_warning_acknowledged=true`。

S3 v4 的唯一新決策欄位是 `recommend_poc`：5 分制加權分 `>= 3.75`、信心至少 `medium`、沒有 PoC blocker，且已建立可稽核的 registered-recipe 報價單。這代表「技術上具備受控 PoC 資格」，不是工作負載適配性或正式採用建議。`poc_review_notes` 仍會記錄 Region 或 pricing 的不確定性。`recommend_low_risk_validation`、`eligible_for_poc_review`、`recommend_s4` 與 `eligible_for_paid_poc_review` 只為讀取舊 artifact 相容，不能作為新的第二條流程。

## 4. S4 現在做什麼

S4 讀 S3 artifact，先建立不會建立資源的 approval gate artifact。Skill 4 唯一可執行路徑是受控、可能產生成本的 PoC，因此部署前一定需要具名核准。

S4 會檢查：

- S3 是否為 `recommend_poc=true`。
- source URL、score、confidence、stop conditions 是否存在。
- 若要求 PoC，是否有真人 `approved_by`。
- 成本模型與 Skill 4 部署 recipe 是否成對註冊。
- 目標 Region 是否已確認，或是否由 approval 明確承認 `region_unknown` 風險。
- 已有報價時，S4 預設帶入報價的預期總額與高情境向上取整後的建議核准上限；人工仍必須具名核准。有效成本上限取 Skill 3 建議、人類核准、內建 sandbox ceiling 三者最小值。
- 沒有報價模型時，S4 不得把 USD 3 policy ceiling 說成 AWS 成本估算。

目前 S4 永遠不會自動建立 AWS resources。即使 PoC gate 通過，也只會標成 `poc_ready_for_manual_start`。

## 5. 這次本機驗證怎麼跑

```powershell
cd "C:\Users\youhs\Documents\實習專案\radar-redesign"

python -m agentic_cloud_radar.cli s1 `
  --input .\samples\landscape-ga-singapore-request.json `
  --output .\out\s1-region-warning-check.json

python -m agentic_cloud_radar.cli s2 `
  --input .\out\s1-region-warning-check.json `
  --output .\out\s2-region-warning-check.json
```

接著準備一份 shortlist request。這份檔案只需要由人類挑一個 candidate。

```powershell
python -m agentic_cloud_radar.cli s3 `
  --input .\out\s2-region-warning-check.json `
  --shortlist .\out\s3-local-shortlist-request.json `
  --output .\out\s3-local-evaluate.json

python -m agentic_cloud_radar.cli s4 `
  --input .\out\s3-local-evaluate.json `
  --output .\out\s4-local-validate.json
```

本機 gate 驗證結果會是：

- S3：`evaluated`，每個候選都有 Skill 3 報價單或 `needs_registered_cost_model` 資料缺口。
- S4：`awaiting_poc_approval` 或 `ready_for_manual_poc_review`；前者不代表另一種低風險 Skill 4，只代表尚未取得部署授權。
- cloud resources created：false，直到另行執行 `s4-deploy --execute`。

## 6. 可以宣稱與不能宣稱

可以宣稱：

- S3/S4 本機 Skill slice 已能讀前一階段 artifact、產出報價與受控 PoC gate JSON。
- Region unknown 不再卡住 S3，而是留下部署提醒；付費 S4 仍需 Region 已確認或具名 approval 明確承認風險。
- S4 目前沒有建立 AWS 資源，cleanup 狀態為不適用。

不能宣稱：

- 不能說正式 PoC 已完成。
- 不能把一個 sandbox recipe 的結果外推到所有環境。
- 不能說 candidate 已在新加坡可用。
- 不能把 `PoC 成本估算報價單` 說成 AWS 帳單、發票或正式銷售報價；實際成本仍待部署後核對。
