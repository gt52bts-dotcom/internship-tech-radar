# S1-S4 程式碼導讀

這份文件只說明目前可執行的核心。五個 Skill 的完整操作契約以 `skills/` 內各自的 `SKILL.md` 為準。

## 核心模組

| 模組 | 責任 |
| --- | --- |
| `s1.py` | 從可信公開來源掃描或匯入候選，建立 run lineage。 |
| `s2.py` | 將候選整理成可比較卡片與官方證據，不自動選出贏家。 |
| `s3.py` | 評估一個人類選定候選，建立固定 rubric 與完整 PoC 報價。 |
| `costing.py` | 產生可追溯的 static public rate-card estimate。 |
| `s4.py` | 建立 PoC gate，檢查成本、Region、核准與 recipe。 |
| `s4_deployer.py` | 執行受控部署、驗證、Console review packet、cleanup 與 abort。 |
| `s5.py` | 僅根據 artifact 渲染 interim、final 或 forced-cleanup 報告。 |
| `cli.py` | 將上述能力包成明確的 CLI 操作。 |

## Run lineage

Skill 1 建立 `run_id`。Skill 2 到 Skill 5 必須保留同一個 run ID，並在使用上游 artifact 前驗證 hash、stage 和候選 ID。建議所有輸出存入同一個 `out/run/` 資料夾，但不同 run 不得混放。

## 單項評估

Skill 1 與 Skill 2 可以有多個候選。從 Skill 3 開始，`shortlist.json` 雖保留歷史名稱，內容必須是人類選定的一個 candidate ID。程式拒絕空選擇或多選；沒有自動 top-3 或全候選 PoC 流程。

## 受控 PoC

Skill 4 不是本機或文件驗證的別名。它是唯一會建立受控 AWS 資源、可能產生成本的階段。部署前要完成成本報價、核准、有效成本上限、recipe 登錄與第二次 `--execute`。

部署完成後必須走 packet-bound Console review：建立 review packet、截 Infrastructure Composer、由人類判讀並確認、使用 `s4-close --execute` 清理同一個 run。新版 runtime 缺少截圖 metadata 或 `display_channel_confirmed` 時，Skill 5 不得輸出 actual-PoC `final`。

## 讀碼順序

1. 先讀一個 Skill 的 `SKILL.md`。
2. 讀相對應的 `sN.py` 與測試。
3. 對 S4，再讀 `s4_deployer.py`、`scripts/s4-capture-infrastructure-composer.mjs` 與 `docs/s4-完整PoC部署操作.md`。
4. 對 S5，確認 report 的結論是否有足夠 runtime 與 billing evidence。
