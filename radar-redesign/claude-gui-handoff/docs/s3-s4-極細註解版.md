# Skill 3 / Skill 4 操作導讀

## 一句話分工

Skill 3 評估人類選定的一項候選，並先完成完整 PoC 報價；Skill 4 才是在明確核准後建立受控 AWS 資源的唯一 PoC 階段。

## Skill 3

輸入是同一個 run 的 Skill 2 artifact，以及一份只含一個 `selected_candidate_ids` 的人類選擇檔。沒有選擇、空選擇或多選都會停止，不會自動挑選候選。

輸出使用固定技術 rubric：

| 項目 | 權重 | 意義 |
| --- | ---: | --- |
| `technical_value` | 0.35 | 官方證據支持的技術價值 |
| `adoption_prerequisites` | 0.25 | 導入前提與已知限制 |
| `verifiability` | 0.25 | 是否能用小型受控測試驗證 |
| `risk_and_stop_conditions` | 0.15 | 風險與具體停止條件 |

Skill 3 的唯一新決策欄位是 `recommend_poc`。它要求加權分至少 3.75、信心至少 `medium`、沒有 PoC blocker，且已取得登錄 recipe 的完整報價。這只代表技術上可進行受控 PoC，不代表工作負載適配、採購核准或正式採用建議。

每個可進入 Skill 4 的候選都必須先有：

- `quote_id`、有效期限、低／預期／高情境總額。
- 可追溯項目、單價、數量、公式、假設與排除項。
- 引用的官方價格來源、計價 Region 與 `live_pricing_api_used`。
- 建議的核准上限。

沒有成本模型時，報價狀態必須是 `needs_registered_cost_model`，不可自行編造價格。公開牌價預估預設是 static rate card，不是 AWS 帳單、正式採購報價或即時 Pricing API 回覆。

## Skill 4

Skill 4 的 `s4` 指令只產生 validation / approval gate artifact，不會建立 AWS 資源。實際部署還需要：

1. Skill 3 的 `recommend_poc=true` 與正確 lineage。
2. 同時具備成本模型和 deployment recipe 的已登錄候選。
3. 有效成本上限：Skill 3 建議、人類核准與 sandbox ceiling 三者的最小值。
4. 具名人類核准 `deployment_authorized=true`。
5. 另一次 `s4-deploy --execute`。

未知 Region 需由核准人設定 `region_warning_acknowledged=true`；明確不支援的 Region 則不得部署。現行核心只部署 artifact 指定的一個目標 Region，沒有自動跨 Region fallback。

## 部署後的 Console review

部署通過自動驗證後，建立 `s4-console-review-packet`。它指定 Infrastructure Composer、輸出位置與 `review_deadline`。Playwright 會隱藏 Console chrome，截取中間 canvas，對紅遮後 PNG 做 SHA-256，再將圖片顯示給具名人類。

人類確認後執行 `s4-close --execute`。此命令需要 runtime、packet、evidence JSON、具名確認人與 `--shared-via gui|conversation`。程式驗證 run ID、stack、Region、必要畫面、hash 與 redaction contract；它不會自動理解圖片內容。

清理只處理 run-derived stack 與其測試資料，並重新查核。新版 runtime 只有 cleanup、截圖 metadata 與 `display_channel_confirmed` 都齊全時，Skill 5 才輸出 actual-PoC `final`。

## 中止路徑

`s4-abort --execute` 只能用於 review deadline 已過、部署失敗或正常 close 失敗。deadline 類型中止必須帶回 packet 供 CLI 檢查。中止後即使 cleanup 已驗證，Skill 5 也只能輸出 `final_without_console_review`，不能當成完成 Console review 的 PoC。
