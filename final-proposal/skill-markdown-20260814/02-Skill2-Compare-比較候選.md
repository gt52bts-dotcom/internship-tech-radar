# Skill 2 Compare｜把多個候選放到同一把尺上

## 一句話定位

Skill 2 把 Skill 1 產生的候選技術整理成比較矩陣。它不替人選答案，而是讓人可以用同一組標準看出差異。

## 人類應該怎麼理解

如果只看每篇新聞本身，幾乎每個新功能都會看起來很有用。Skill 2 的價值是把候選放在同一張桌上比較：哪個技術比較成熟、哪個比較有實作路徑、哪個成本或 Region 資訊比較清楚、哪個其實還缺關鍵證據。

它把「很多看起來都不錯」變成「可以清楚挑一個核心候選進深評」。

## 它實際做什麼

- 檢查輸入是否來自 Skill 1，並保留同一個 `run_id`。
- 為每個候選建立提案卡：能力、交付形式、成熟度、預期效益、前提、限制與停止條件。
- 重新檢查候選相關官方文件，不只吃搜尋結果。
- 建立固定欄位的比較矩陣，讓候選用同一把尺比較。
- 標示 Region、價格、文件、限制與實作缺口。

## 亮點

- **同一把尺**：避免只因為某篇文章寫得漂亮，就看起來比較值得做。
- **不自動選冠軍**：AI 整理比較，人類保留選題權。
- **把風險提前攤開**：缺少價格、Region、實作方式或 stop condition 的候選，不會被美化。
- **支撐單一候選流程**：Skill 1 / Skill 2 可以看很多候選，但 Skill 3 之後一次只處理人類選定的一個核心。

## 這關不做什麼

- 不幫人決定哪個一定要做。
- 不開始評分或 PoC。
- 不把缺少 Region 證據直接判成不可用，也不把它判成可用。
- 不把 pricing page 當成完整 PoC 報價單。

## 案例中可以怎麼講

- 成功案例中，Lambda 和 S3 Files 都不是靠「新」被放行，而是因為後續能定義清楚 PoC 問題與資源邊界。
- 停止案例中，WorkSpaces 和 Quick Suite 的風險會在 Skill 2 / Skill 3 被放大檢查：前者有成本與可逆性問題，後者有實作細節不足問題。

## 交付物

- `s2.json`
- 候選提案卡
- 比較矩陣
- Region / 價格 / 文件 / 限制的 review notes
- 給人類挑單一候選的決策材料
