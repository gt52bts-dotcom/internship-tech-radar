# 2026-08-03｜人類與 AI 執行軌跡對比

用途：放入 AI PM／最終成果簡報，呈現同一天中 Cleo 與 AI 的分工差異。這不是聊天紀錄流水帳，而是用 8/3 的實際 Git 與日誌證據整理出的協作軌跡。

## 投影片主標

同一天的協作軌跡：人類定方向，AI 把方向落成可驗證流程

## 一句話重點

8/3 的核心不是 AI 自己完成專案，而是 Cleo 持續指出流程漏洞、決策風險與主管可讀性問題；AI 則把這些修正轉成程式、Skill 規則、報告格式、測試與 GitHub 紀錄。

## 一頁式對比表

| 時段 | Cleo 的人類判斷 | AI PM / 工程執行 | 產出的改變 |
|---|---|---|---|
| 上午 | 要求報告不能只列技術狀態，要讓人看懂新聞價值、成本與限制。 | 重整 Skill 5 報告呈現，改成新聞應用摘要、逐階段證據、成本邊界與後續問題。 | 報告從「工程輸出」變成「主管可審查的證據包」。 |
| 中午 | 指出先選候選、後看報價的流程不合理；也否定信心指標。 | 調整 Skill 3：先產生分數、報價與決策資訊，再讓人決定是否 PoC；移除信心作為判斷依據。 | 決策點從「憑感覺選」變成「看完價值與成本再核准」。 |
| 下午前段 | 指出 Skill 3 報告沒有解釋文章在做什麼，單看分數不夠。 | 加入新聞解釋層：以前／現在／差異、原文重點、最小架構、可能應用情境。 | 技術新聞被轉譯成非工程主管也能理解的內容。 |
| 下午中段 | 要求架構圖要像人能看懂的圖卡，不要只有流程圖或連結。 | 產生並內嵌 PNG 架構圖，改為自包含 HTML 報告，避免圖片只顯示成網址。 | Skill 3 報告能直接拿來做人類 PoC 決策。 |
| 下午後段 | 完成人工確認後，要求清除資源並產生最終報告。 | 執行受控清除、留下清除前用量快照、回查資源不存在，產出 Skill 5 final。 | PoC 不只成功部署，也證明可清除、可回查、可結案。 |
| 傍晚 | 接受 Claude 的審查，但要求只吸收有用的問題，不盲目照單全收。 | 將截圖確認升級為資源盤點：比對實際資源、報價資源、權限面與耗時。 | 驗證從「看起來有截圖」變成「資料結構可稽核」。 |
| 收尾 | 要求日誌不要堆檔名和抽象英文，要能讓人看懂。 | 重寫正式日誌，突出結構性改變、決策、證據與風險。 | 實習成果從「技術流水帳」轉成「專案管理成果」。 |

## 視覺呈現建議

投影片可以做成左右雙軌時間線：

- 左軌標題：Cleo 的決策與校正
- 右軌標題：AI 的落地與驗證
- 中間用箭頭表示「人類判斷轉成 AI 執行」

建議畫面文字：

```text
Cleo：指出問題、設定標準、核准風險
        ↓
AI PM：轉成規則、程式、測試、報告
        ↓
共同成果：可審查、可重跑、可交接的 S1-S5 證據鏈
```

## 長官版講稿

這頁想呈現的是，我不是單純請 AI 代做，而是把 AI 當作專案協作者管理。以 8/3 為例，我負責判斷流程哪裡不合理、報告哪裡看不懂、哪些證據不能誇大；AI 則負責把這些判斷落成程式、報告、測試與 GitHub 紀錄。最後形成的不是一份聊天紀錄，而是一套可以被主管審查、可以重跑、也可以交接給另一台電腦或另一個 AI 的雲端技術評估流程。
