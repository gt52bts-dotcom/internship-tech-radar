### 可貼入表單的「優點／可改善處」

#### 積極自發、持續學習

優點：實習過程中能主動發現問題並拆解成可執行步驟，例如 AWS 權限限制、CloudFormation 部署、Skill 3 成本估算、PoC human gate、cleanup 與報告證據邊界。後期更將 AI 技術雷達整理成五個可重用 Skill，完成成功案例、停止案例、成果發表與服務化缺口整理。

可改善處：後續可把服務化提案補上一次分析成本、可量化效益、內部帳號與權限條件，讓成果更容易被部門評估是否採用。

#### 團隊合作

優點：能依 mentor、主管與會議回饋調整專案方向，將討論結果整理成 checkpoint、文件與可追蹤工作紀錄。成果發表後也能把協理對 `預言者雷達` 的回饋與 AI PM 回饋分開管理，避免混用證據。

可改善處：因單位實習職缺較少，跨同事共同交付情境本來有限，不應作為主要扣分。後續若有正式會議、主管交辦協調或跨單位同步情境，可補充為額外加分證據。

#### 創新求變

優點：能把 AI 工具從單純協助寫作，轉成具備掃描、比較、評估、受控 PoC 驗證與報告的五個 Skill 流程。已建立 Skill 積分、主管評分自評、Evidence Ledger、Human Review Gate、Decision Layer、成本估算、cleanup 規則與互動儀表板，展現能接受新概念並整合成可操作方法的能力。

可改善處：後續可補上公司環境實際採用或主管使用後的成效，例如節省多少整理時間、降低多少溝通落差，或哪一個候選決策因這套流程更容易被驗證。

#### 組織認同

優點：能遵守專案記錄、Git／Notion 同步、17:00 日誌統整、敏感資訊不入檔、private repository、授權與成本 gate 等規範，並主動把成果整理成主管可閱讀的形式。面對公司環境與權限限制，也能調整方案而不是硬推不可行路線。

可改善處：後續可補更多部門活動參與、公司文化理解、內部環境導入條件與部門實際工作情境連結的具體例子。

#### 誠信正直

優點：在專案紀錄中能誠實標示哪些成果已驗證、哪些只是使用者回報、mentor 觀點、協理回饋或待公司環境驗證，也不把 `closed_without_console_review` 寫成正常 Console-reviewed final。對 API key、AWS credentials、secret value 等敏感資訊維持不寫入 repo、日誌或聊天內容的原則。

可改善處：後續可持續在對外報告與 final proposal 中保留「已驗證／待驗證／估算」標籤，避免成果表述過滿。

### 綜合回饋建議

實習期間展現出高度主動性與學習意願，能把模糊任務拆成可驗證的工作步驟，並在 AWS 權限、部署、評估、PoC、cleanup 與報告整理上持續留下可回查證據。專案不只停留在技術實作，也逐步建立 `預言者雷達`五個 Skill、AI PM、Skill 積分、主管自評與儀表板等追蹤機制，使成果更容易被主管檢視與延續。8/14 成果分享後，協理回饋肯定此方向能把 GPT 式零散提問整理成受控流程；後續若能補上公司內部環境落地、一次分析成本與可量化效益，整體評核會更完整。
