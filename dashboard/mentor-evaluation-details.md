### 可貼入表單的「優點／可改善處」

#### 積極自發、持續學習

優點：實習過程中能主動發現問題並拆解成可執行步驟，例如 AWS 權限限制、Step Functions 流程錯誤、CloudFormation 部署、CLI schema 查證與成本估算。遇到問題時不只等待指示，而是會查官方文件、執行驗證、整理替代方案，並把結果轉成日誌、教學書、demo checklist 與 final proposal 素材。

可改善處：後續可把每日學習再更明確地對應到主管期待或部門需求，讓主動探索不只停留在技術驗證，也能更快轉成可被部門採用或評估的成果。

#### 團隊合作

優點：能依 mentor 與使用者回饋調整專案方向，例如暫停保單穩定性題目、改做 S3 Files 新聞截斷測試，並將討論結果整理成 checkpoint、文件與可追蹤的工作紀錄。也能把複雜技術內容整理成主管可讀的語言，方便團隊同步。

可改善處：因單位實習職缺較少，跨同事協作情境本來有限，不應作為主要扣分。後續若有正式會議、主管交辦協調或跨單位同步情境，可補充為額外加分證據。

#### 創新求變

優點：能把 AI 工具從單純協助寫作，轉成具備專案管理、評分、驗證與治理追蹤的工作流程。已建立 Skill 積分、主管評分自評、Evidence Ledger、Human Review Gate、Decision Layer、evaluation harness 與互動儀表板，展現能接受新概念並整合成可操作方法的能力。

可改善處：後續可補上公司環境實際採用或主管使用後的成效，例如節省多少整理時間、降低多少溝通落差，或哪一個決策因這套流程更容易被驗證。

#### 組織認同

優點：能遵守專案記錄、Git／Notion 同步、17:00 日誌統整、密鑰不入檔與 private repository 等規範，並主動把成果整理成主管可閱讀的形式。面對公司目前無法使用 Bedrock、AWS SCP 權限限制等條件，也能調整方案而不是硬推不可行路線。

可改善處：目前組織認同的證據較偏工作流程與規範遵守，後續可補更多部門活動參與、公司文化理解、與部門實際工作情境連結的具體例子。

#### 誠信正直

優點：在專案紀錄中能誠實標示哪些成果已驗證、哪些只是使用者回報或待公司環境驗證，也不把未部署的 template validation 寫成部署成功。對 API key、AWS credentials、secret value 等敏感資訊維持不寫入 repo、日誌或聊天內容的原則。

可改善處：後續可持續在對外報告與 final proposal 中保留「已驗證／待驗證／估算」標籤，避免成果表述過滿。

### 綜合回饋建議

實習期間展現出高度主動性與學習意願，能把模糊任務拆成可驗證的工作步驟，並在 AWS 權限、部署、評估與報告整理上持續留下可回查證據。專案不只停留在技術實作，也逐步建立 AI PM、Skill 積分、主管自評與儀表板等追蹤機制，使成果更容易被主管檢視與延續。單位只有一個實習職缺，因此團隊合作應以 mentor 對齊、主動回報與文件同步來評估；後續若能增加主管使用回饋與公司環境採用後成效，整體評核會更完整。
