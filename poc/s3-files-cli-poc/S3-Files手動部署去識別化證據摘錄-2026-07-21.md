# S3 Files 手動部署去識別化證據摘錄

日期：2026-07-21  
來源：使用者提供的 PowerShell / EC2 terminal 輸出  
安全處理：原始輸出含完整 private key、public IP、private IP、account ID、ARN 與 resource IDs，不能提交、轉貼或放入報告。本文只保留去識別化證據。

## 結論

本次手動 CLI PoC 已完成 AWS News Blog「S3 bucket accessible as file system」的核心驗證：

```text
S3 bucket object
-> S3 Files file system
-> VPC mount target
-> EC2 Amazon Linux mount path
-> 從 mount path 寫檔回 S3
```

已驗證：

- S3 Files file system 為 `available`。
- EC2 instance 為 `running`，instance/system status 為 `ok / passed`。
- EC2 可 SSH 登入 Amazon Linux 2023。
- EC2 成功安裝 `amazon-efs-utils 3.1.3`。
- EC2 成功以 `sudo mount -t s3files ... /mnt/s3files` 掛載 S3 Files。
- `/mnt/s3files` 顯示為 `nfs4` 掛載。
- EC2 mount path 可讀到原本在 S3 的 `hello-from-s3.txt`。
- EC2 mount path 寫入 `hello-from-mount.txt` 後，PowerShell 可從 S3 讀回該檔案。

## 重要證據摘錄

### 1. S3 Files resource available

PowerShell 查詢 S3 Files file systems，顯示同一個測試 bucket 下有 S3 Files file system，狀態為 `available`。

```text
fileSystemId: [REDACTED]
bucket: [REDACTED_TEST_BUCKET]
status: available
roleArn: [REDACTED]
```

備註：原始輸出同時顯示完整 account ID、file system ARN 與 role ARN，已全部遮蔽。

### 2. EC2 client ready

EC2 狀態查詢顯示 instance 已啟動，且 system / instance reachability 通過。

```text
State: running
System: ok
Instance: ok
SystemReach: passed
InstanceReach: passed
```

備註：原始輸出含 EC2 instance ID、public IP、subnet、VPC、security group、instance profile ARN，已全部遮蔽。

### 3. SSH 登入與套件安裝

EC2 登入後顯示 Amazon Linux 2023，並成功安裝 S3 Files mount 所需套件：

```text
Amazon Linux 2023
Installed:
  amazon-efs-utils-3.1.3-1.amzn2023.x86_64
  stunnel-5.58-1.amzn2023.0.2.x86_64
```

備註：原始輸出含 public IP、private IP、登入來源 IP 與 private key 修復過程；報告不可保留原文。

### 4. S3 Files mount 成功

EC2 上執行 mount 後，`df` 與 `findmnt` 顯示 `/mnt/s3files` 已掛載。

```text
Filesystem      Size  Used Avail Use% Mounted on
127.0.0.1:/     8.0E     0  8.0E   0% /mnt/s3files

TARGET       SOURCE      FSTYPE
/mnt/s3files 127.0.0.1:/ nfs4
```

說明：`127.0.0.1:/` 是 mount helper 呈現方式，可作為成功掛載證據；不是錯誤。

### 5. S3 -> EC2 mount 可讀

EC2 mount path 列表中出現 S3 原始檔案：

```text
/mnt/s3files
  hello-from-s3.txt
```

並可讀出內容：

```text
hello from S3 at [TIMESTAMP]
```

路徑釐清：

- 錯誤路徑：`/mnt/s3files/poc/hello-from-s3.txt`
- 正確路徑：`/mnt/s3files/hello-from-s3.txt`

原因是 file system 建立時已指定 S3 prefix，因此 mount 根目錄已對應到該 prefix。

### 6. EC2 mount -> S3 可寫回

EC2 在 mount path 寫入：

```text
hello-from-mount.txt
hello from mounted S3 Files [TIMESTAMP]
```

PowerShell 後續查詢 S3 顯示：

```text
hello-from-mount.txt
hello-from-s3.txt
```

並可從 S3 讀回：

```text
hello from mounted S3 Files [TIMESTAMP]
```

這是本次最關鍵的端到端證據：EC2 以檔案系統路徑寫入，最後在 S3 object 端讀回。

## 過程中踩到但已解決的問題

### EC2 內不能照抄 PowerShell AWS CLI 指令

EC2 的 shell 是 bash，不支援 PowerShell 的反引號續行與 `$Profile` / `$Region` 變數寫法；且 EC2 內的 AWS CLI 版本或 plugin 也可能沒有 `s3files` command group。

正確做法：

- `aws s3files ...` 查詢放在本機 PowerShell 執行。
- EC2 只負責 Linux 套件安裝、mount、讀寫檔案。

### private key 格式曾錯誤

第一次 SSH 失敗原因是 private key 被寫成單行，導致 `invalid format`。後續已重建 PEM 多行格式並修正檔案 ACL，SSH 成功。

安全判斷：

- 原始 pasted text 已包含完整 private key，該 key 應視為已暴露。
- cleanup 前若還需要截圖，請先保留證據；cleanup 後應刪除 EC2 key pair 與本機 `.pem`。

### S3 object key 曾多一個斜線

錯誤：

```powershell
s3://[BUCKET]/poc//hello-from-mount.txt
```

修正：

```powershell
$ObjectKey = "${Prefix}hello-from-mount.txt"
aws s3 cp "s3://$Bucket/$ObjectKey" - --profile $Profile --region $Region
```

## 後續安全與 cleanup 建議

在完成必要截圖後，建議 cleanup：

- terminate EC2 instance。
- delete S3 Files mount target。
- delete S3 Files file systems。
- delete EC2 key pair。
- delete local `.pem`。
- delete IAM instance profile / roles / inline policies。
- delete route table / internet gateway / subnet / VPC。
- delete S3 test objects / bucket。

cleanup 前需由使用者確認，避免刪掉還需要截圖的資源。
