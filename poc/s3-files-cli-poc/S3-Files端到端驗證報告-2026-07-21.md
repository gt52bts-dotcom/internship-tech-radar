## 結論

本次已不只停在閱讀新聞或建立 AWS resource，而是完成 S3 Files 的端到端行為驗證：

```text
S3 bucket
-> S3 Files file system
-> S3 Files mount target
-> EC2 instance mount path
-> 從 mount path 寫檔回 S3 bucket
```

也就是說，新聞中「making S3 buckets accessible as file systems」這個主張，已在 intern AWS 帳號中用 CLI 與 EC2 實際驗證成功。

已完成：

- 建立測試 S3 bucket。
- 啟用 bucket versioning。
- 啟用 SSE-S3 encryption。
- 上傳 `hello-from-s3.txt` 至 bucket 的測試 prefix。
- 建立 S3 Files service role。
- 建立 S3 Files file system。

- 建立 S3 Files mount target。
- 建立 EC2 client 並成功 SSH。

- 從 EC2 mount path 讀到 S3 既有檔案。
- 從 EC2 mount path 寫入新檔案，並在 S3 bucket 讀回。

## 關鍵證據

### S3 -> EC2 mount

EC2 上成功 mount 後，`df` / `findmnt` 顯示 `/mnt/s3files` 為 NFS4 掛載：

```text
Filesystem      Size  Used Avail Use% Mounted on
127.0.0.1:/     8.0E     0  8.0E   0% /mnt/s3files

TARGET       SOURCE      FSTYPE
/mnt/s3files 127.0.0.1:/ nfs4
```

EC2 mount path 可讀到原本從 S3 上傳的檔案：

```text
cat /mnt/s3files/hello-from-s3.txt
hello from S3 at 2026-07-20T16:57:18...
```

說明：因 file system 建立時已指定 S3 prefix `poc/`，所以 `/mnt/s3files` 根目錄對應到 S3 的 `poc/`，不是 `/mnt/s3files/poc/`。

### EC2 mount -> S3

EC2 mount path 寫入：

```text
hello-from-mount.txt
hello from mounted S3 Files 2026-07-21T06:18:12+00:00
```

回到 PowerShell 後，S3 bucket 可列出並讀回該檔案：

```text
hello-from-mount.txt
hello-from-s3.txt

hello from mounted S3 Files 2026-07-21T06:18:12+00:00
```

此證據代表 `mount -> S3` export 成功。同步不是即時，但本次等待後已可在 S3 讀回。

## 技術理解

本次 PoC 驗證出三個重點：

1. S3 Files 不是單純 S3 API wrapper。它需要 VPC、mount target、security group 與 NFS 2049。
2. 建立 file system 時若綁定 S3 prefix，mount path 的根目錄會對應到該 prefix。
3. S3 與 mount path 雙向同步可用，但存在同步延遲，因此不能當成零延遲檔案同步機制。
